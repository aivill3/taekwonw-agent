# config — 설정

모든 튜닝 값의 단일 출처. 여기 있는 모듈은 프로젝트의 **어떤 것도 임포트하지
않는다.** 그래야 설정이 코드에 의존하지 않고 순환 임포트도 생기지 않는다.

| 파일 | 담는 것 |
|---|---|
| `settings.py` | 환경변수, 경로, API 자격증명, 네트워크 |
| `collect_config.py` | 수집량, 조회 기간, 랭킹 기준 |
| `draft_config.py` | 모델 체인, 분량 임계값, 요청 간격 |
| `quality_config.py` | 검사 통과 기준 (`CheckConfig`, `SeoConfig`) |

## 값을 추가할 위치

```
.env 로 바꿀 수 있어야 하는가        → settings.py
수집량·선별 기준인가                 → collect_config.py
생성 분량·모델 선택인가              → draft_config.py
검사 통과 기준인가                   → quality_config.py
특정 모듈 안에서만 쓰는 구현 상수인가 → 그 모듈에 그대로 둔다
```

마지막 줄이 중요하다. 정규식 패턴, 태그 집합 같은 구현 세부는 config로 올리면
오히려 읽기 어려워진다. **다른 모듈이 함께 봐야 하는 값만** 여기 둔다.

## `quality_config.py` 가 config에 있는 이유

초안 생성(`agents/drafting`)이 `SeoConfig` 를 만들어 검사기에 넘긴다. 분량과
챕터 수는 소재 정보량에 따라 초안마다 달라지므로, 프롬프트에 지시한 값을 그대로
검사 임계값으로 써야 한다. 그러지 않으면 "1,300자로 쓰세요"라고 시킨 뒤
"1,600자 미만입니다"라고 경고하는 모순이 생긴다.

설정이 `agents/quality` 안에 있으면 `drafting` 이 `quality` 를 임포트하게 되어
에이전트끼리 얽힌다. 설정만 올려서 양쪽이 여기를 보게 했다.

## ⚠️ SEO 임계값의 성격

`quality_config.py` 의 숫자들은 **"네이버가 요구하는 기준"이 아니다.** 업계에
도는 SEO 규칙(글자 수 임계값, 감성 비율)은 네이버 공식 문서에 근거가 없다.

여기 값은 태권월드 기존 발행 글을 실측해서 나온, **기존 글과 스타일을 일치시키기
위한** 기준이다. 이 구분이 흐려지면 나중에 임계값을 조정할 때 판단 근거가 사라진다.

## 분량 값이 두 계통인 이유

초안 생성 에이전트가 둘이고 서로 다른 분량 정책을 쓴다.

| | 적용 대상 | 방식 |
|---|---|---|
| `SCHEMA_*` | `schema_draft_agent` | 원문 길이 × 1.8배, 상한 2,000자 |
| `LENGTH_TIERS` | 자유 텍스트 계열 | 원문 정보량 4구간별 목표 범위 |

`SCHEMA_MAX_LENGTH = 2000` 은 Notion rich_text 속성 1개의 하드 리밋이라 임의로
올릴 수 없다. `LENGTH_TIERS` 의 하위 구간(1,000~1,400자)은 이 상한과 무관하게
"얇은 소재에 고정 분량을 요구하면 LLM이 빈칸을 지어낸다"는 실측에서 나왔다.
