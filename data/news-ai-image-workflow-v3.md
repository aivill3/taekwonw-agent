# 뉴스 기반 AI 이미지 자동 편집 워크플로우 (v3)

## 전체 구조

검증 완료된 내부 자산 라이브러리를 도입하면서 파이프라인이 **두 개의 트랙**으로 분리됩니다.

**A. 오프라인 트랙 — 자산 등록 (건별 실행 아님)**
```
자산 수집 → 등록 심사 → 전처리(마스크·포즈·뎁스) → 메타데이터 작성 → 라이브러리 편입
```

**B. 런타임 트랙 — 기사 1건당 실행**
```
1 기사 분석 → 2 Visual Plan → 3 라이브러리 조회 → 4 마스크 로드
→ 5 프롬프트 컴파일 → 6 인페인팅+컴포짓 → 7 검수 게이트 → 8 표시·출력
                                    ↑___________|  실패 시 재시도
```

**v2 대비 핵심 변화:** GroundingDINO·SAM2·포즈 추출이 런타임에서 오프라인으로 이동합니다. 자산이 고정되어 있으므로 마스크를 매번 계산할 이유가 없습니다. 건당 처리 시간이 크게 줄고, 마스크를 사람이 한 번 검수해 고정할 수 있어 결과가 안정됩니다.

**스타일 방침:** 실사풍(photorealistic)을 유지합니다. 일러스트 전환은 사용하지 않습니다. 대신 특정 경기로 오인될 소지는 **식별 단서 제거**(문자·로고·대회 엠블럼·연도 표기)와 캡션 고정 문구로 통제합니다.

# A. 오프라인 트랙 — 자산 라이브러리 구축

## A-1. 폴더 구조

```
assets/
├── sparring/          # 겨루기
├── poomsae/           # 품새
├── demonstration/     # 시범
├── event/             # 행사·시상
├── interview/         # 인터뷰·인물
├── fallback/          # 인물 없는 폴백 자산
└── _registry.json     # 전체 인덱스
```

이미지 1장당 딸린 파일 세트:

```
sparring/tkd_spar_042.jpg          # 원본
sparring/tkd_spar_042.keep.png     # keep 마스크
sparring/tkd_spar_042.edit.png     # edit 마스크
sparring/tkd_spar_042.pose.png     # OpenPose 스켈레톤
sparring/tkd_spar_042.depth.png    # Depth 맵
sparring/tkd_spar_042.json         # 메타데이터
```

## A-2. 등록 심사 체크리스트

라이브러리 편입 전 사람이 확인합니다. 이 관문이 v2의 0단계·라이선스 검증·종목 정합성 검증을 모두 대체합니다.

**종목 정합성 (가장 중요)**
- [ ] 도복 상의가 V넥 풀오버 형태인가 — 앞자락을 겹쳐 여미는 가라테 기(gi) 배제
- [ ] 가드가 주먹을 쥔 형태인가 — 손바닥을 펴서 막는 가라테식 방어 배제
- [ ] 스탠스가 측면 지향이고 발 간격이 좁은가 — 정면 앞굽이 배제
- [ ] 두 선수 간 거리가 실제 겨루기 간격에 부합하는가
- [ ] 호구·헤드기어 형태가 좌우 동일한 구조인가

**법적 요건**
- [ ] 라이선스 문서 확보 (출처 URL, 사진가, 라이선스 전문, 취득 일시)
- [ ] 모델 릴리스 확보 또는 얼굴 비노출 확인
- [ ] 촬영 장소·대회 식별 요소 부재 (또는 edit 영역으로 처리 가능)

**기술 요건**
- [ ] 얼굴이 비노출이거나 헤드기어로 가려지는가
- [ ] 배경이 단순하여 재구성 여지가 큰가
- [ ] 해상도가 최종 출력 규격 이상인가
- [ ] 모션블러·초점이 인페인팅에 지장을 주지 않는가

> **수집 시 주의:** 범용 무료 스톡에서 `martial arts`로 검색하면 대부분 가라테·주짓수가 나옵니다. `taekwondo sparring`, `taekwondo kyorugi`로 쿼리를 한정하고, 그래도 섞여 들어오는 결과는 위 종목 정합성 체크리스트로 걸러냅니다.

## A-3. 전처리 (등록 시 1회)

**활용 기술:** GroundingDINO + SAM2 + Human Parsing(SCHP/Sapiens) + OpenPose/Depth Anything + OpenCV

**처리 흐름:**
1. GroundingDINO로 `person` 검출 → SAM2로 인물 세그멘테이션 (배경은 반전으로 획득, 직접 탐지하지 않음)
2. Human Parsing으로 도복·호구·헤드기어·보호대를 부위별 분리
3. 3계층 마스크 구성:

| 계층 | 대상 | 처리 |
|---|---|---|
| `keep` | 사지 실루엣, 관절 위치, 신체 비율 | 절대 보존 (6단계 컴포짓으로 복원) |
| `edit` | 배경, 도복, 호구, 헤드기어, **얼굴** | 자유 재생성 |
| `soft` | 두 계층 경계 ±8~15px | feather 블렌딩 |

4. `edit` 영역에 dilate(3~15px) → 가우시안 블러로 feather 처리
5. OpenPose 스켈레톤 / Depth 맵 추출
6. **사람이 마스크 육안 검수** — 여기서 고정된 마스크가 이후 모든 생성에 재사용되므로, 이 시점의 품질이 곧 라이브러리 품질입니다

> 얼굴은 반드시 `edit`에 포함합니다. 보존하면 초상권 리스크가 남습니다. 헤드기어로 덮는 방향으로 재생성하면 비식별화와 화질을 동시에 확보할 수 있습니다.
> `keep`을 "인물 전체"로 잡지 않습니다. 그러면 인물 위에 얹힌 도복·호구가 함께 잠겨 장비 일반화가 불가능해집니다.

## A-4. 메타데이터 스키마

3단계 자산 선택이 외부 API 검색에서 **DB 필터링**으로 바뀌므로, 이 필드가 곧 검색 조건입니다.

```json
{
  "id": "tkd_spar_042",
  "category": "sparring",
  "subject_count": 2,
  "composition": "eye_level_side",
  "shot": "medium",
  "aspect_ratio": ["16:9", "1:1"],
  "face_visible": false,
  "face_reason": "headgear_worn",
  "sport_verified": true,
  "background_complexity": "low",
  "license": {
    "source_url": "...",
    "photographer": "...",
    "license_type": "...",
    "model_release": true,
    "acquired_at": "2026-08-07T09:00:00Z"
  },
  "usage_log": ["2026-07-02", "2026-08-01"],
  "notes": "왼쪽 선수 돌려차기, 오른쪽 방어. 배경 단순."
}
```

`aspect_ratio`를 배열로 두는 이유: 안전하게 크롭 가능한 비율을 미리 기록해두면, Visual Plan이 요구하는 비율로 자를 수 있는지 런타임에 판단할 필요가 없습니다.

## A-5. 커버리지 매트릭스

`카테고리 × 구도 × 인원수 × 종횡비` 표를 만들고 빈칸을 채우는 방식으로 수집합니다.

- **최소 목표: 셀당 3장.** 그래야 로테이션이 돌아가고 동일 이미지가 반복 노출되지 않습니다
- 빈 셀은 3단계 조회 0건으로 나타나므로, 운영하면서 자연스럽게 수집 우선순위가 드러납니다
- `fallback/`에는 인물 없는 자산(도복 정물, 도장·경기장 시설, 매트 클로즈업)을 미리 확보합니다

# B. 런타임 트랙

## 1단계: 뉴스 기사 입력 및 분석 (Analysis Stage)

**주요 역할:** 기사의 핵심 맥락을 파악하고 이미지 선택 및 생성을 위한 메타데이터를 추출합니다.

**활용 기술:** Gemini API (구조화 출력)

**처리 흐름:**
- 뉴스 URL 또는 본문 텍스트 입력
- 기사 제목/본문 요약 및 핵심 키워드 추출 (태권도, 겨루기, 무주, 결승전 등)
- 카테고리 분류: 겨루기 / 품새 / 시범 / 행사 / 인터뷰 등 사전 정의된 라벨
- **구조화 출력 강제:** enum 기반 structured output으로 라벨 흔들림 방지, confidence 미달 시 `기타`로 폴백
- **고유명사 추출 및 격리:** 실명·소속·상표명·대회명·연도를 별도 필드로 분리 보관. 이 목록은 프롬프트로 전달되지 않으며, 5단계 하드 필터와 7단계 검수의 **금칙어 사전**으로만 사용됩니다

## 2단계: Visual Plan 생성 (Visual Planning)

**주요 역할:** 기사 해석을 "만들 그림의 사양"으로 변환합니다. 3단계 조회 조건과 5단계 프롬프트의 **단일 진실 원천**입니다.

**활용 기술:** Gemini API (구조화 JSON 출력)

**처리 흐름:**

원본 관찰값이 아니라 **일반화된 사양**을 생성합니다. 일반화는 이 단계에서 완료되며, 5단계로 미루지 않습니다.

| 필드 | 내용 | 예시 |
|---|---|---|
| `scene` | 장면 유형 | 경기장 내 겨루기 순간 |
| `subject_count` | 인물 수 | 2 |
| `composition` | 구도·앵글 | eye-level 측면, 미디엄 샷 |
| `mood` | 조명·색감 | 실내 스포트라이트, 차가운 색온도 |
| `aspect_ratio` | 종횡비 | 16:9 |
| `forbidden` | 금지 요소 | 문자, 로고, 대회 엠블럼, 연도 표기, 식별 가능한 얼굴 |

**일반화 원칙 (관찰값 → 사양값)**

| 관찰값 (1단계 격리 대상) | Visual Plan 값 |
|---|---|
| LED wall with "WORLD TAEKWONDO GP…", "Muju 2025" | `large LED wall with abstract light panels, no text, no logos` |
| KPNP chest guards, branded dobok "KOREA" | `unbranded electronic chest protectors (blue vs red), plain white dobok` |
| 특정 대회명·연도 | `generic indoor competition arena` |

- **종횡비는 반드시 이 시점에 확정합니다.** 생성 후 크롭하면 구도가 깨집니다

## 3단계: 라이브러리 조회 및 자산 선택 (Asset Retrieval)

**주요 역할:** Visual Plan 조건에 맞는 검증 완료 자산을 라이브러리에서 선택합니다.

**활용 기술:** `_registry.json` 필터링 + CLIP 유사도 스코어링

**처리 흐름:**
1. 1차 필터: `category` = 1단계 분류 결과
2. 2차 필터: `subject_count`, `composition`, `aspect_ratio` 포함 여부, `sport_verified = true`
3. 3차 필터: `usage_log` 기준 최근 N개월 사용분 제외
4. 남은 후보를 Visual Plan 텍스트와 CLIP 유사도로 정렬, 최상위 1장 선택
5. **조회 0건 시 폴백 우선순위**
   - 같은 카테고리의 다른 구도
   - 인접 카테고리 (겨루기 ↔ 시범)
   - `fallback/` 인물 없는 자산
6. 선택 결과를 `usage_log`에 기록

라이선스·provenance는 등록 시점에 확정되어 있으므로 런타임 검증이 불필요합니다.

## 4단계: 마스크 로드 및 조정 (Mask Loading)

**주요 역할:** 사전 계산된 마스크와 컨디셔닝 자산을 불러옵니다. 생성이 아니라 로드입니다.

**활용 기술:** OpenCV (크롭·리사이즈 연산만)

**처리 흐름:**
- `.keep.png` / `.edit.png` / `.pose.png` / `.depth.png` 로드
- Visual Plan의 `aspect_ratio`에 맞춰 원본과 마스크·컨디셔닝을 **동일 파라미터로** 크롭·리사이즈
- 재시도 3회차 진입 시에만 `edit` 마스크에 추가 dilate 적용 (기본 경로에서는 조정 없음)

## 5단계: 인페인팅 프롬프트 컴파일 (Prompt Compilation)

**주요 역할:** Visual Plan을 모델이 소비할 형태로 **번역**합니다. 새로운 창작을 하는 단계가 아닙니다.

**활용 기술:** Gemini API + 규칙 기반 금칙어 필터

**처리 흐름:**
- Visual Plan(2단계) + `edit` 대상 목록(4단계)을 결합해 프롬프트 생성
- **2단계와 역할이 겹치지 않도록 한정합니다.** 둘 다 독립적으로 생성하면 계획과 프롬프트가 어긋납니다
- **하드 필터:** 1단계에서 격리한 고유명사 목록으로 최종 대조. LLM 재작성은 확률적으로 새어나가므로 규칙 기반 차단을 뒤에 둡니다
- **모델별 포맷 분기:** FLUX Fill은 서술형 자연어, SDXL Inpainting은 태그형 + negative prompt

**종목 정합성 고정 문구 (필수 포함)**

이전 테스트에서 가라테 문법이 남는 문제가 확인되었습니다. 라이브러리 심사로 1차 차단하되, 프롬프트에서도 재확인합니다.

```
taekwondo dobok with V-neck pullover top and black collar, not a wrap-style karate gi
both athletes guard with closed fists held at chest height
side-facing sparring stance, narrow foot spacing
matching electronic chest protectors on both athletes, same panel structure, shoulder straps visible
packed arena with full spectator stands
```

**negative:** `text, letters, numbers, logos, watermark, banner, scoreboard, karate gi, open palm block`

## 6단계: 인페인팅 및 컴포짓 (Generation & Compositing)

**주요 역할:** `edit` 영역을 재생성하고, `keep` 영역을 원본 픽셀로 복원한 뒤 조명을 정합시킵니다.

**활용 기술:** FLUX Fill (또는 SDXL Inpainting) + ControlNet(OpenPose/Depth) + OpenCV

**처리 흐름:**
1. `[원본 + 3계층 마스크 + 5단계 프롬프트 + ControlNet 컨디셔닝]`으로 인페인팅
2. **ControlNet으로 포즈 고정.** 마스크만으로는 포즈가 보존되지 않습니다. `edit`을 넓게 잡을수록 실루엣이 흔들리므로 "마스크는 넉넉히, 포즈는 컨디셔닝으로" 구조가 필요합니다
3. **알파 컴포짓 복원.** 인페인팅 모델은 VAE 인코딩/디코딩 과정에서 마스크 밖 픽셀도 미세하게 열화시킵니다. `keep` 영역을 원본 픽셀로 되돌리고 `soft` 계층에서 블렌딩합니다
4. **하모나이제이션.** 배경 교체 후 색온도·명암 방향 보정. 생략하면 합성 티가 납니다

> **대안 트랙:** FLUX.1 Kontext, Qwen-Image-Edit, Gemini 계열 지시문 기반 편집 모델은 마스크 없이 동작합니다. 라이브러리 방식에서는 마스크가 이미 준비되어 있어 마스크 트랙의 비용 이점이 커졌지만, 카테고리별 A/B 비교는 여전히 유효합니다.

## 7단계: 자동 검수 게이트 (Automated QC Gate)

**주요 역할:** 리스크를 자동 판정하고 불합격 시 재시도 경로로 되돌립니다. 판정 결과는 반드시 다음 행동으로 연결되어야 합니다.

**활용 기술:** OCR(PaddleOCR/EasyOCR) + Face Embedding(ArcFace) + CLIP + 규칙 엔진

| 항목 | 판정 방법 | 불합격 조건 |
|---|---|---|
| 문자 노출 | OCR 전면 스캔 | 문자 검출됨 — LED 문구, 배너, 스코어보드 숫자, 생성 모델이 만든 가짜 글자 포함 |
| 대회 식별 단서 | 로고·엠블럼 검출 + 1단계 금칙어 대조 | 특정 대회·연도 식별 가능 |
| 초상권 | 원본 vs 결과 face embedding 코사인 유사도 | 임계값 초과 (비식별화 실패) |
| Visual Plan 부합 | 결과물 vs Plan CLIP 유사도 | 임계값 미달 |
| 종목 정합성 | 도복 형태·가드 자세 | **자동 검출 곤란 → 사람 승인으로 이관** |
| 좌우 장비 일치 | 호구 형태 동일성 | **자동 검출 곤란 → 사람 승인으로 이관** |
| 해부학 오류 | 손가락·관절 꺾임 | **자동 검출 곤란 → 사람 승인으로 이관** |

**재시도 정책 (단계적 강도 상승)**
- 1~2회차: seed 변경 후 **6단계** 재실행
- 3회차: `edit` 마스크 확장 후 **4단계**부터 재실행
- 4회차: 라이브러리 차순위 자산으로 **3단계**부터 재실행
- 최종 실패: `fallback/` 자산으로 전환

**사람 최종 승인:** 자동 검수는 필터일 뿐입니다. 게이트 통과 후 human-in-the-loop 승인을 전제로 설계합니다.

## 8단계: 표시 및 최종 출력 (Labeling & Output)

**주요 역할:** AI 생성 사실을 표시하고 웹 최적화 형태로 저장합니다. 검수와 분리된 독립 산출 단계입니다.

**활용 기술:** Pillow / ImageMagick, C2PA 툴체인, IPTC 메타데이터

**처리 흐름:**
- **가시적 표시:** 고정 캡션 부착
  > "AI로 생성한 이미지이며 특정 경기·인물과 무관합니다."

  실사풍을 유지하는 이상 이 문구가 오인 방지의 핵심 장치입니다. 자유 문구가 아니라 템플릿으로 고정하세요
- **비가시적 표시:** IPTC `digitalSourceType: trainedAlgorithmicMedia` + C2PA 서명
- **외부 모델 워터마크 정책 확정:** Gemini 등 일부 모델은 가시 워터마크를 삽입합니다. 크롭으로 제거하더라도 비가시 워터마크(SynthID 등)는 남으므로, 제거 여부와 자체 표시 병행 여부를 정책으로 명시해두세요
- **웹 최적화:** WebP/AVIF 변환, 반응형 리사이즈, SEO 파일명
- **alt 텍스트 자동 생성:** 1단계 키워드 재활용
- **아카이빙:** 자산 ID, 생성 파라미터(seed, 모델 버전, 프롬프트), 검수 로그, 승인자를 함께 보관

**표시 의무 관련 참고**
- 한국 「인공지능 발전과 신뢰 기반 조성 등에 관한 기본법」 제31조는 생성형 AI 결과물에 대한 사전 고지·표시 의무를 규정하며 2026년 1월 22일 시행되었습니다. 표시는 가시적 방식(자막·로고·워터마크)과 비가시적 방식(메타데이터·디지털 워터마크) 중 선택할 수 있습니다
- 의무 주체는 "AI 사업자"이며, AI를 단순 도구로 활용하는 이용자는 현행법상 의무 대상이 아닙니다. 다만 이 워크플로우를 **서비스 형태로 타인에게 제공**하는 경우 사업자에 해당하게 됩니다
- 현재 1년 이상의 계도기간이 운영 중이며 과태료 부과는 유예되어 있습니다. 정확한 적용 여부는 시행령·가이드라인 원문 및 법률 자문으로 확인이 필요합니다
- 가시+비가시 표시를 기본값으로 두면 규제 강화나 해외 트래픽 유입 시 소급 대응이 필요 없습니다
