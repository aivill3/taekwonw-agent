# 보드 승인 구조 (B단계)

## 무엇이 바뀌었나

`content` 가 Content 를 바로 만들지 않고, 뉴스 DB의 **`묶음` 슬롯에 배정**만 한다.
사람이 보드에서 카드를 끌어 고친 뒤 `confirm` 으로 확정하면 그때 Content 가 생긴다.

```
collect → content → [보드에서 드래그] → confirm → [승인 체크] → publish
                     ↑ 새로 생긴 단계
```

## 파일 배치

| 파일 | 위치 | 상태 |
|---|---|---|
| `notion_store.py` | `tools/` | 교체 (`묶음` 속성 추가) |
| `content_workflow.py` | `workflows/` | 교체 (묶음 배정으로) |
| `confirm_workflow.py` | `workflows/` | **신규** |
| `run.py` | 루트 | 교체 (`confirm` 추가) |

## 묶음 슬롯

| 슬롯 | 용도 | 개수 |
|---|---|---|
| `단독1` ~ `단독6` | 긴 기사 1건 = 한 편 | 6칸 |
| `묶음1` ~ `묶음4` | 짧은 기사 4건 = 한 편 | 4칸 |
| `보류` | 발행하지 않을 기사 | — |
| (비어 있음) | 미배정. 확정 대상 아님 | — |

하루 최대 10편이다. Gemini 2.0 Flash RPD 20 기준으로 재시도까지 감안한 상한이다.

날짜를 라벨에 넣지 않은 이유는 select 옵션이 매일 늘어나는 것을 막기 위해서다.
슬롯을 재사용하고 보드 뷰에 `상태 = 선정됨` 필터를 걸면 오늘 것만 보인다.

## Notion 설정

### 1. 속성 자동 생성

`content` 를 한 번 돌리면 `ensure_schema()` 가 `묶음` 속성을 만든다. 수동 작업 없음.

### 2. 보드 뷰 만들기

뉴스 DB에서 뷰 추가 → 보드 →

| 설정 | 값 |
|---|---|
| 그룹화 기준 | `묶음` |
| 필터 | `상태 = 선정됨` |
| 카드 미리보기 | 페이지 콘텐츠 |
| 표시 속성 | **`묶음상태`**, `소주제1`, `키워드점수`, `날짜` |

`묶음상태` 를 표시 속성에 넣어야 카드 아래에 판정 문구가 보인다.

`상태 = 선정됨` 필터가 핵심이다. 확정된 기사는 `콘텐츠연결`로 넘어가 보드에서 사라지고,
슬롯이 비어 다음 회차에 재사용된다.

### 3. 확정 버튼 (선택)

지금은 `run.py confirm` 을 직접 실행한다. 버튼으로 하려면 폴링 러너가 필요하며
다음 단계에서 붙인다.

## 카드에 승인 가능 여부 표시하기

Notion 은 조건부 문구를 실시간으로 띄우지 못한다. 대신 두 가지를 함께 쓴다.

| 방법 | 갱신 | 보이는 것 |
|---|---|---|
| Notion 기본 건수 | **실시간** | 칸 제목 옆 `묶음1  5` |
| `묶음상태` 속성 | `--check` 실행 시 | 카드 아래 `✅ 승인 가능` / `⚠️ 승인 불가` |

```powershell
uv run python run.py confirm --check
```

Content 를 만들지 않고 판정 문구만 기록한다. 상태도 바꾸지 않는다.
카드를 옮긴 뒤 다시 돌리면 갱신된다.

| 상황 | 문구 |
|---|---|
| 단독 1건 + 소주제 4개 | ✅ 승인 가능 |
| 묶음 정확히 4건 | ✅ 승인 가능 |
| 묶음 1~3건 또는 5건 이상 | ⚠️ 승인 불가 |
| `보류` 칸 | ⏸️ 보류 |
| 미배정 | ◻️ 미배정 |

같은 슬롯의 카드는 모두 같은 문구를 받는다. 어느 카드를 보든 이 묶음이
승인 가능한지 알 수 있어야 하기 때문이다.

## 확정 규칙

`confirm` 이 슬롯마다 검사한다. Notion 보드는 "한 칸에 4개까지"를 막지 못하므로
코드가 대신 본다.

| 슬롯 | 조건 | 위반 시 |
|---|---|---|
| `단독N` | 기사 1건 **+ 소주제 4개** | 슬롯 통째로 건너뜀 |
| `묶음N` | 기사 **정확히 4건**, 모두 소주제 있음 | 슬롯 통째로 건너뜀 |
| `보류` | 검사 없음 | 상태를 `보류`로 |
| 미배정 | 검사 없음 | 그대로 둠 |

거부된 슬롯은 **상태를 바꾸지 않는다.** 보드에서 고친 뒤 다시 확정하면 된다.
일부만 처리하면 어디까지 됐는지 추적할 수 없어서 전부 아니면 전무로 간다.

검증 결과 (합성 데이터):

```
단독1   1건  통과  단독 1건 · 소주제 4개
단독1   1건  거부  소주제 1개 (단독은 4개 필요)
단독2   2건  거부  단독 슬롯에 2건 (1건이어야 함)
묶음1   4건  통과  묶음 4건
묶음1   3건  거부  묶음 슬롯에 3건 (4건이어야 함 — 1건 부족)
묶음2   5건  거부  묶음 슬롯에 5건 (4건이어야 함 — 1건 초과)
묶음3   4건  거부  소주제 없는 기사 1건
```

## Content 컬럼은 확정 시점에 계산한다

`기사수`, `목표분량`, `선정이유` 는 묶음 전체의 값이라 드래그하면 즉시 달라진다.
`content` 단계에서 미리 써 두면 카드를 옮긴 순간 낡은 값이 되므로,
`confirm` 이 실제 배치로 `DraftBrief` 를 다시 만들어 계산한다.

Content DB 컬럼은 이전과 동일하게 전부 채워진다.

| 컬럼 | 출처 |
|---|---|
| 콘텐츠제목 | `⏳ {첫 소주제} 외 N건` → publish 가 초안 제목으로 교체 |
| 상태 / 승인 | `승인대기` / 체크박스 |
| 유형 | 단독 슬롯 → 주제형, 묶음 슬롯 → 날짜형 |
| 선정이유 | `[묶음1] 묶음 4건` |
| 원문기사 | Relation |
| 원문ID | page_id 목록 (코드용) |
| 기사수 / 원문길이 / 목표분량 | 확정 배치로 재계산 |
| 소주제1~5 | 확정 배치의 소주제 |
| 대표URL / 작성모델 / 형태소 | 기존과 동일 |

## 실행 순서

```powershell
# 1. 묶어서 보드에 배정
uv run python run.py content --dry-run   # 결과만 확인
uv run python run.py content             # 실제 배정

# 2. Notion 보드에서 카드 드래그로 조정
#    - 4건 넘게 넣지 않기
#    - 발행 안 할 기사는 '보류' 칸으로

# 3. 배치 점검 — 카드에 승인 가능/불가 표시
uv run python run.py confirm --check
#    보드에서 ⚠️ 를 찾아 고치고 다시 --check

# 3-1. 로그로만 확인하려면 (아무것도 안 씀)
uv run python run.py confirm --dry-run

# 4. 확정 → Content 생성
uv run python run.py confirm

# 5. Content DB 에서 '승인' 체크 후
uv run python run.py publish
```

## 상태 흐름

```
News:  수집됨 → 선정됨 ──(content)──> 선정됨 + 묶음 슬롯
                            │
                            ├─(confirm 통과)→ 콘텐츠연결 → 작성완료
                            ├─(보류 칸)────→ 보류
                            └─(거부)───────→ 선정됨 그대로 (고쳐서 재시도)

Content: 승인대기 →(승인 체크 + publish)→ 작성완료
```

## 슬롯 부족

`content` 가 배정할 슬롯이 모자라면 그 묶음은 배정하지 않고 로그에 남긴다.

```
슬롯 부족으로 3편 미배정 (단독 6칸 · 묶음 4칸)
```

앞선 것들이 확정되어 `콘텐츠연결`로 빠지면 자리가 나므로, `confirm` 후
`content` 를 다시 돌리면 된다. 슬롯을 늘리려면 `notion_store.BUNDLE_SOLO_SLOTS` /
`BUNDLE_GROUP_SLOTS` 의 range 를 키우면 되지만, RPD 20 제약을 먼저 고려할 것.
