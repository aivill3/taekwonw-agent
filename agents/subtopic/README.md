# subtopic — 소주제 생성 (LLM #1)

승인된 기사를 3~4개 소주제로 나눈다. 사람이 승인 게이트에서 판단할 재료다.

## 소주제 개수를 원문 길이에 맞추는 이유

짧은 단신에서 4개를 뽑으면 서로 겹치고, 그 소주제로 쓴 글도 같은 사실을
되풀이한다. 실측: 600자 단신 → 4개 소주제 → 섹션 1·2가 동일 내용 반복.

`config/draft_config.py` 의 `SUBTOPIC_LONG_BODY`(1,200자)를 경계로 4개/3개를
가른다.

## 배치 처리

무료 티어 RPD는 **요청 건수** 기준이라, 3건을 한 요청에 묶으면 RPD 소모가
1/3로 줄어든다. TPM(250K)은 여유가 커서 토큰은 제약이 아니다.

배치 응답은 `article_index` 로 기사와 매칭한다. LLM이 순서를 바꾸거나 일부를
빠뜨릴 수 있으므로 인덱스 없이 순서에 의존하면 안 된다. 배치가 실패하거나 일부만
돌아오면 남은 기사는 개별 호출로 처리한다.

`SUBTOPIC_BATCH_SIZE=1` 로 두면 개별 호출과 동일하게 동작한다. 품질 문제가
의심될 때 되돌리기용이다.

## 프롬프트

`prompts/subtopic/single.md`, `prompts/subtopic/batch.md` 에 있다. 응답 스키마는
`SUBTOPIC_RESPONSE_SCHEMA` 로 API 레벨에서 강제하므로 파싱이 깨지지 않는다.
