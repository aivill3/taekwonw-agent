# agents — 판단·생성 단위

각 에이전트는 하나의 결정을 내린다. 외부 I/O는 `tools` 에 위임하고, 임계값은
`config` 에서 읽는다.

**에이전트끼리 직접 임포트하지 않는다.** 공통으로 필요한 것이 생기면 `core` 나
`tools` 로 내리거나, 값이면 `config` 로 올린다. 조합은 `workflows` 의 일이다.

| 폴더 | 결정하는 것 | LLM |
|---|---|---|
| `collecting/` | 이 기사를 쓸 수 있는가 (날짜, 본문 품질) | — |
| `ranking/` | 어떤 기사를 고를 것인가 | — |
| `subtopic/` | 이 기사를 어떤 소주제로 나눌 것인가 | #1 |
| `drafting/` | 소주제로 어떤 글을 쓸 것인가 | #2 |
| `quality/` | 이 초안을 내보내도 되는가 | — |
| `illustration/` | 어떤 그림을 붙일 것인가 | (선택) |

LLM을 쓰는 곳은 두 군데뿐이다. 나머지는 전부 결정론적이라 같은 입력이면 같은
결과가 나온다. 사람이 승인 게이트에서 판단하려면 이 성질이 필요하다.

## 에이전트를 추가할 때

1. `agents/<이름>/` 폴더와 `README.md` 를 만든다
2. 진입점은 `<이름>_agent.py`
3. 임계값은 `config/` 에, 프롬프트는 `prompts/` 에
4. 외부 호출이 필요하면 `tools/` 에 클라이언트를 먼저 만든다
5. `workflows/` 에서 호출을 끼워 넣는다

3번을 건너뛰면 나중에 값을 바꾸려고 소스를 뒤지게 된다. 4번을 건너뛰면 다른
에이전트가 그 호출 코드를 가져다 쓰면서 결합이 생긴다.
