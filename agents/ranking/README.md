# ranking — 기사 선별

수집된 기사 중 무엇을 쓸지 고른다. LLM을 쓰지 않는다.

## 3단계

```
1. 주제 판정    태권도가 '주제'인 기사인가 (단순 언급 배제)
2. 점수 계산    당일 트렌드 키워드 기반
3. 사건 클러스터링   같은 사건 기사를 묶어 대표만 남김
```

## 주제 판정이 제목을 따로 보는 이유

제목에 도메인 키워드가 있으면 본문 기준을 완화한다(`MIN_DOMAIN_HITS_NO_TITLE`
대신 `MIN_DOMAIN_HITS`). 태권도 기사인데 본문에서 "태권도"를 두어 번만 쓰는
경우가 있고, 반대로 다른 종목 기사가 태권도를 한 번 언급하는 경우도 있다.

## 사건 클러스터링

같은 대회를 여러 매체가 보도하면 시그니처 토큰이 겹친다. 유사도가
`MAX_SIMILARITY` 를 넘으면 한 사건으로 묶고, 본문이 가장 긴 기사를 대표로
삼는다. 보도 건수(`report_count`)만큼 대표에 가점을 준다 — 여러 매체가 다뤘다는
것 자체가 중요도 신호다.

대표 선정에 점수가 아니라 본문 길이를 먼저 보는 이유: 초안 생성 단계에서 원문이
짧으면 LLM이 사실을 지어낸다. 정보량이 많은 쪽을 남겨야 한다.

## 조사 처리

`_strip_particles()` 는 어절 끝 조사를 잘라낸다. 다만 잘라낸 뒤 2글자 미만이
되면 원형을 유지한다. 과절단하면 "대회를" → "대"처럼 무의미한 토큰이 생긴다.

형태소 분석기(Kiwi)를 쓰지 않는 이유는 속도다. 랭킹은 수십~수백 건을 훑는데,
여기서 Kiwi를 돌리면 파이프라인 전체가 느려진다. 품질 검사 단계에서는 정확도가
중요하므로 Kiwi를 쓴다.
